# Linux desktop parity

Run `scripts/linux_smoke.sh` from a checkout with Docker running. It builds the tracked working tree and writes each session's frame, document state and Vulkan adapter report under `build/linux-smoke/{x11,wayland}/`. Select one session with `scripts/linux_smoke.sh wayland`. An optional second argument selects the output directory. Xvfb and Weston run inside the container. The Wayland session has no X display and Weston starts without Xwayland.

## Platform conditionals

The native shell has 44 exact `#[cfg(target_os = "macos")]` sites after sharing the model-menu state query, including the hidden PDF/probe window. The following groups account for them all.

| Source | Sites | Linux behavior and limits |
| --- | ---: | --- |
| main.rs | 19 | AppKit menu modules, creation, event dispatch, recent-file and extension-menu updates are Mac-specific. Linux exposes the command registry, extension actions and recents in the application. The desktop entry provides Open With and New Window. File operands are forwarded to a running instance through the Unix socket. Winit also handles dropped files. Linux has no Finder process serial number, Dock delegate, global AppKit menu or macOS window-tab group. Normal windows use compositor decorations. Test windows request hidden/inactive presentation where supported. |
| menu.rs | 1 | AppKit's application menu and system Services use the macOS menu bar. Linux and Windows draw an egui menu bar above the document tabs. It uses the same ordered commands, model entries and imports as the installed macOS menu. Window controls use winit. System Services remains macOS-only. |
| menu_commands.rs registration in native.rs | 1 | The portable menu registers command IDs and factory shortcuts with the same window command registry. Shortcuts rebind there. Extension queries use per-window rows. |
| python.rs | 1 | Both menu bars reflect model checks. The separate extension-update query synchronizes AppKit. The renderer already receives the extension rows for its own window. |
| native.rs, modal input | 4 | AppKit modifier conversion, nested event pumping and posted keys have Linux paths for blocking questions and scripted answers. GTK presents the question on its own thread so winit's Wayland or X11 connection has one event-loop owner. During synchronous progress, an independent XI2 subscription or a private Wayland queue delivers window-local pointer motion and button events to the progress chrome. Winit retains ownership of its own event queue. |
| native.rs, clipboard | 4 | GTK/GDK implements clipboard read, write and type discovery on both display servers, including application model data and plain text. The private test clipboard is process-local. Without a Wayland input seat the system clipboard is unavailable. GTK 3 itself queries a keyboard during initialization, so a seatless Wayland session bypasses GTK clipboard initialization. Cross-application exchange and retention after exit require a desktop-session test. |
| native.rs, window chrome | 3 | AppKit background color, click-through test-window ordering and system window tabs are macOS-specific. Linux uses winit window attributes, its desktop app ID or WM_CLASS, and the application's document tabs. Wayland compositors control placement and stacking. The shell's GPU-drawn chrome remains available. The older Qt/AppKit glass panels live outside these Rust gates. There is no compositor blur implementation. |
| native.rs, application hooks | 2 | Linux dispatches launch arguments, winit close events and desktop file associations. Double-click registration includes native Built documents and projects. macOS Dock quit and Finder URL callbacks have no Linux delegate. |
| native.rs, scrolling | 2 | Linux accepts wheel and raw touch events from winit. Raw touchscreen contacts feed the shared touch handler. Wayland pointer-gestures pinch updates are converted from absolute scale to incremental zoom. Winit supplies two-finger scroll phases. Wayland finger-axis frames supply release velocity for a decaying momentum tail, using the shared sub-pixel carry and inertia preference. Rotation and smart zoom are unavailable. Physical input devices were outside the compositor smoke. |
| platform_paths.rs | 4 | The Linux implementations resolve preferred languages from the environment, documents through xdg-user-dir, and application data and caches through XDG paths with home-directory fallbacks. |
| keys.rs | 1 | Linux uses Control for shortcuts and Super for Meta. macOS swaps the platform modifiers. |
| launcher.rs | 2 | Native window handles select Wayland, Xlib or XCB for GPU surfaces. Batch exports and probes use an inactive hidden window. Linux has no AppKit activation policy. |

A compositor smoke exercises file loading, menu activation by clicking rendered controls, surface creation and frame capture using Mesa software Vulkan. It does not measure physical GPU performance or exercise a desktop shell's launcher, menu, clipboard manager or touch hardware.
