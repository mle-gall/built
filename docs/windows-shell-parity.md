# Windows desktop shell

The Windows installer targets x64. The table covers the native shell, Explorer registration, process handoff, and graphics selection. The runtime checks in the last column require a Windows desktop.

| Area | Implementation | Remaining Windows checks and gaps |
| --- | --- | --- |
| Menus | The egui application menu above the document tabs uses the AppKit command model, recent documents, model checks and extension contributions. The window command registry owns shortcuts. Minimize, maximize/restore and fullscreen call winit. | Exercise mouse selection, shortcut rebinding, focus after a modal dialog and multiple windows. There is no Win32 HMENU, native Alt-letter menu mnemonic table or system Services menu. |
| Explorer | Inno Setup advertises `.built` and `.builtproject` under OpenWithProgids and registers both, plus `.igz`, in Default Apps. They use the installed document icon and the existing quoted `built.exe "%1"` verb. HKA follows per-user or machine-wide installation. The portable ZIP does not register handlers. | Install, upgrade and uninstall in both scopes. Check Open With and double-click a Unicode path containing spaces. Verify that an existing user-selected handler survives. |
| Single instance | A normal launch reserves a local named pipe before Python starts. The logon SID names the pipe and restricts its ACL. Later processes check the server's logon, grant it foreground permission where Windows permits, and send an absolute UTF-16 path or an activation request. The primary acknowledges after queuing the event. Explicit new windows, private settings and scripted launches bypass the pipe. If IPC fails, the launching process can still open its own window. | A Windows-only test exercises two consecutive clients against an isolated pipe. Run it on Windows and verify Explorer handoff, rapid launches, foreground behavior and session separation. |
| DX12 and Vulkan | Both backends are compiled into wgpu. The renderer uses `PRIMARY` unless `WGPU_BACKEND` selects a backend, and requests an adapter compatible with the window surface. The Win32 surface carries both HWND and HINSTANCE. | On Windows run `built --probe-gpu` and a scripted frame capture separately with `WGPU_BACKEND=dx12` and `WGPU_BACKEND=vulkan`. The probe reports availability. Adapter selection and device creation depend on the installed drivers. |

For the x64 MSVC target, check each crate's binaries, libraries and tests with `cargo check --locked --all-targets --target x86_64-pc-windows-msvc`, once with `--no-default-features` and once with `--all-features`. Supply the manifest for `rust/built_app`, `rust/built_render` or `rust/built_core`. The renderer and core each expose an `extension-module` feature. The launcher has no crate-local feature switches.
